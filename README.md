# open-rtu

An open, sub-£100 reference Remote Terminal Unit (RTU) for grid-side frequency compliance monitoring of offshore wind turbines.

This repository is the reproducibility bundle for the manuscript *"An Open, Formally-Derived Reference Instrument for Grid-Side Frequency Compliance Monitoring of Offshore Wind Turbines: Replay Validation Against NESO Blackout-Event Records"* (submitted to MDPI *Sensors*, 2026). Every headline figure in the paper is regenerable from the scripts and captures released here.

## Overview
Grid-side frequency compliance at offshore wind sites is measured today by proprietary RTUs whose internal signal chains cannot be independently inspected. This project is a fully open alternative: a dual-ESP32 instrument whose every stage — from a Kirchhoff-derived signal-conditioning chain, through a seven-module measurement firmware hierarchy implementing IEC 61400-21 Class I/II parameters, to a Python SCADA interface carrying DNP3 (IEEE 1815) telemetry under IEC 61400-25 logical-node mapping — is formally derived, physically built, and empirically validated. 

Validation uses a replay methodology: the National Energy System Operator's published one-second record of the 9 August 2019 GB blackout event is replayed through a second ESP32 acting as a disturbance generator, serving as simultaneous stimulus and ground truth. Statistical equivalence to the NESO reference within the IEC 61400-21 Class II band is established by Two One-Sided Tests, supported by bootstrap cross-validation, Bland–Altman agreement, and Total Vector Error characterisation against IEEE C37.118.1. The methodology is shown to generalise to a second independent event (22 December 2023).

## Repository layout

- `firmware/` — Feather 1 measurement builds (V2 canonical, V6 parallel dual-core FreeRTOS) and the Feather 2 disturbance generator (`feather_2_code_mimoDEMO`).
- `analysis/` — the analysis and capture toolchain: TOST and bootstrap, sensitivity sweep, Bland–Altman, TVE, four-algorithm comparison, Cramér–Rao-bound analysis, swing-equation inertia recovery, runtime metrics, repeatability, and NESO-window extraction.
- `trajectories/` — NESO-derived replay trajectories (canonical 9 Aug 2019, 22 Dec 2023, and balanced/THD-varied three-phase variants) as `.csv` and Feather `.h` headers.
- `captures/` — raw replay captures and their analysis JSON sidecars.
- `figures/` — the paper's data figures, regenerable from the scripts above.
- `hashes.txt` — SHA-256 manifest of every file in this release.

## Reproducing the results

The three headline results can be reproduced directly from the released captures: 

- python analysis/tost_sweep.py captures/replay_20260627_102507V2.csv
- python analysis/bland_altman.py captures/replay_20260627_102507V2.csv
- python analysis/analyse_v6_repeatability.py

Each table and figure in the paper's results section is regenerated by a named script against a named, hashed capture; see `hashes.txt` for the manifest.

## Note on the SCADA HMI

`hmi/SCADA_HMI.py` targets the V2 canonical telemetry format. The V6 parallel firmware emits a compact 20 ms REPORT stream that is parsed by the analysis scripts (e.g. `analyse_v6_repeatability.py`) rather than by the live HMI. 
Updating the HMI to consume the V6 stream is tracked as future work.
